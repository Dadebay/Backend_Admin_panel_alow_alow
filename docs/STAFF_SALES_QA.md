## Воспроизведение браузерной проверки

1. Подготовить пустую локальную базу с именем, заканчивающимся на `_test`,
   отдельный Redis DB 15 и локальный MinIO. Задать `TEST_DATABASE_URL`,
   `TEST_REDIS_URL`, `TEST_S3_ENDPOINT`. В проведённой проверке использовались
   порты 55439, 56399 и 59000 соответственно. Это временные QA-службы.
2. Применить миграции и собрать приложения:

   ```bash
   DATABASE_URL="$TEST_DATABASE_URL" npm --prefix apps/api run db:deploy
   npm --prefix apps/api run build
   npm --prefix apps/admin run build
   ```

3. В отдельном терминале запустить fixture. Скрипт отвергает нелокальные службы,
   базу без суффикса `_test` и непустую базу. Он не удаляет существующие данные.
   Тестовая сессия записывается вне репозитория с правами 0600:

   ```bash
   STAFF_SALES_QA_SESSION=/tmp/a7-staff-sales-qa/session.json node apps/api/scripts/staff-sales-qa.mjs
   ```

4. Для проверки консоли запустить print-agent без токена прямой печати:

   ```bash
   cd apps/print-agent
   env -u A7_TAGAM_RECEIPT_AGENT_TOKEN go run . -listen 127.0.0.1:17873 -origins http://127.0.0.1:4174 -api-url http://127.0.0.1:4015/api/v1 -dispatch-dir /tmp/a7-staff-sales-qa/print-dispatch -log-dir /tmp/a7-staff-sales-qa/print-logs -connect-printers=false
   ```

5. Из корня репозитория выполнить:

   ```bash
   STAFF_SALES_QA_SESSION=/tmp/a7-staff-sales-qa/session.json ADMIN_QA_PRODUCTION=1 npm --prefix apps/admin run test:playwright -- tests/browser/staff-sales-real-api.spec.ts --workers=1
   ```

6. Остановить fixture, print-agent и созданные QA-службы. Не запускать полный
   API test одновременно с fixture: global setup пересоздаёт тестовую базу.

Fixture воспроизводит пять заказов на 1555 TMT, созданных 6 октября с возвратом
денег 7 октября, и четыре заказа 7 октября на 588 TMT. Ещё 26 небольших заказов
проверяют пагинацию 25 + 10 строк и постоянный итог 2403 TMT за еду.
Эти данные синтетические; они не являются выгрузкой рабочей базы.
